## 2025-05-23 - MFA Authentication Bypass
**Vulnerability:** The 2FA verification endpoint (`verify-2fa`) previously relied on a user-provided `userId` or `tempToken` (which was also just a `userId`) to identify the user completing the second factor. An attacker with knowledge of a user's ID could potentially bypass the first factor (password) or perform targeted brute-force attacks against the 2FA code if they knew the target's user ID.
**Learning:** Multi-step authentication flows must cryptographically link the different stages. Relying on client-provided identifiers for the second stage allows an attacker to jump directly to that stage, bypassing the security controls of the previous stage.
**Prevention:** Use short-lived, signed, and purpose-bound tokens (e.g., an `mfaToken` JWT) to bridge the stages of a multi-factor authentication flow. The token should be generated only after the first factor is successfully validated and should contain the necessary context (like `userId` and `hotelId`) for the subsequent stage.

## 2025-05-24 - MFA Authentication Bypass and Brute-force Risk
**Vulnerability:** The MFA verification endpoint (`verify-2fa`) previously accepted a raw `userId` or `tempToken` which was not cryptographically secured, potentially allowing an attacker who knows a user's ID to bypass the first factor (password) and proceed directly to brute-forcing the second factor. Additionally, failed MFA attempts were not being recorded, making the 6-digit TOTP code vulnerable to brute-force attacks.
**Learning:** Authentication flows with multiple stages must securely link those stages using signed, short-lived tokens (e.g., an MFA token) to ensure the first stage was successfully completed before allowing the second stage. Every authentication challenge must also be protected by the account lockout policy.
**Prevention:** Always use a signed JWT or similar secure token to transition between login phases. Ensure `UserManagementService.recordFailedLogin` is called on all authentication failures, including MFA verification.
